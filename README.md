# 截图翻译

iOS 快捷指令：截屏 → OCR → 文本清洗 → Google 翻译 → 复制并显示。
不装任何第三方 App，全部使用系统自带动作。`.shortcut` 文件由 Python 脚本生成，可在任意平台构建。

## 用法

两条路线，运行时自动区分：

- **直接运行**：现场截屏，按比例裁掉顶部通知栏和底部导航栏，翻译整屏内容。要在目标 App 里触发才有意义——**返回轻点**（设置 → 辅助功能 → 触控 → 轻点背面）、**操作按钮**或辅助触控悬浮球都可以。从快捷指令 App 点运行，截到的是快捷指令 App 自己
- **选区翻译**：截图 → 点缩略图 → 拖裁剪框 → 完成 → 分享 → 选本快捷指令，只翻译你框选的区域

译文自动复制进剪贴板，并用快速查看弹出（标题固定为「翻译结果」），可滚动可选中，段落结构保留。翻译空手而归时，改为复制原文并通知。清洗后凑不满 3 个字母的（图标残迹、纯数字之类）不翻译，直接通知收场。

## 安装

未签名的 `.shortcut` 不能直接导入——iOS 15 起系统不再允许在设备上签名，签名只能出设备。`installer.py` 生成的 `导入快捷指令.shortcut` 把这件事收成一个动作：接住分享过来的文件，gzip 后发给远程签名服务（[Shortcut Source Helper](https://routinehub.co/shortcut/10060/) 里「Remote Sign」的同款通道），签好的文件直接交给快捷指令 App，名字取自文件名。全程不弹菜单，也不依赖其他快捷指令。

1. 安装 [Shortcut Source Tool](https://www.icloud.com/shortcuts/e6fdda8687cf49b4a4c965995b70c051) 和它依赖的 [Shortcut Source Helper](https://www.icloud.com/shortcuts/7125fde0360a49f5994d02fb6d1b1fbd)——只为引导下面这一步，装完都可以删
2. 按「首次导入」把 `导入快捷指令.shortcut` 装进去

## 日常导入

把 `.shortcut` 传到 iPhone（微信 / AirDrop / 文件均可），在「文件」里长按 → **共享** → **导入快捷指令**。

## 首次导入

`导入快捷指令` 自己也是未签名的，得靠 Shortcut Source Tool 引导一次：

1. 把 `导入快捷指令.shortcut` 存进「文件」，然后在快捷指令 App 里运行 Shortcut Source Tool
2. 在 **Get Shortcut Source from** 菜单里选 **📝 File**，选中刚存的文件。不要选 **💫 Shortcut**——那是搜索已经装进库的快捷指令，此时库里还没有，只会得到 "No shortcuts found"
3. 选择 **Edit/Restore Source**
4. 选择 **Skip**
5. 点击右上角 ☑️ 按钮，为 shortcut 命名后点击 **Done**
6. 选择 **Remote Sign**，签名完成后即加入快捷指令库

## 自定义

改 `build.py` 后重新运行 `python build.py` 即可：

- 裁剪比例：`source()` 里两个 math 动作的 `13E-2`（顶部裁掉 13%）和 `735E-3`（保留 73.5%）。写成 E 记数法而非小数，是为了避开小数点在部分地区的解析歧义——用小数写法导入时会被工具拦下来要求转换
- 目标语言：文件头部的 `TARGET`
- 起译门槛：`MIN_LETTERS`，清洗后剔除数字、标点、空白，剩余字符数超过它才翻译
- 弹窗标题：`TITLE`
- 清洗规则：文件头部的正则表（去噪 / 去重 / 空行折叠 / 断行合并 / 段落合并）

## 原理

`.shortcut` 是二进制 plist，`build.py` 直接构造动作数组并序列化，落盘前自检（UUID 引用完整性、条件块配平、变量占位符对齐）。`installer.py` 复用同一套构件和自检。

OCR 清洗链按序执行五步正则替换：

1. **去噪**：删掉不需要翻译的部分——装饰箭头、分隔线、图标被 OCR 成的字符残迹（独占一行的，粘在行首的如 `66 标题文字`，挂在行尾的如 `About me ···`）、状态栏时间和电量之类的纯数字行（`15:45`、`100%`）、身高体重距离这种「数字 + 单位」独占一行的（`164 cm`、`50 kg`、`1 km`），以及含中文的整行。中文残留会让系统把整段判为中文而整体跳过翻译；日文、韩文、泰语、越南语、高棉语的行不受影响
2. **去重**：同一行文本重复出现只保留一次（如 UI 按钮词）
3. **空行折叠**：段落边界折叠为哨兵字符，翻译后还原，保住段落结构
4. **断行合并**：行尾无标点且下行小写开头的 OCR 断行拼回同一句，显著提升译文质量
5. **段落合并**：泰语、高棉语、日文、韩文没有大小写可依，改用行长判断——满行且行尾无句号，说明下一行是同一句的续行

## 翻译

清洗完的文本全部发给 Google 的公开端点——中文行已在去噪阶段整行剔除，走到这一步的都是待译文本。**文本一律出设备**，介意的话别用。

早期版本先走系统翻译、回空值才回退 Google，图的是文本尽量不出设备。撤掉是因为系统翻译有两种失败方式：没装语言包时回空值，回退能接住；不支持的语言**不报错，退化成罗马字音译**，`បើសិនអ្នកល្បី...` 变成 `Chesian Phuharinthikat...`，看起来像译文其实一个字都没翻——有值就不算失败，回退永远不触发。在快捷指令里认不出音译，这条分流就立不住。后来「检测语言 + 中文免译」的分流也撤了：中文既然在清洗时就被剔除，检测这一步只剩空转。

Google 这条走 `translate_a/single` 端点，文本放在 POST 表单里（不进 URL，长文本不会撑爆长度限制），`dj=1` 让响应变成 `{"sentences": [{"trans": ...}], "src": ...}`。`sentences` 是字典列表，直接取键会弹「选取项目」让你手动选，所以要用「重复」逐项取 `trans` 再拼接。换行和段落哨兵原样返回，段落结构不受影响。
